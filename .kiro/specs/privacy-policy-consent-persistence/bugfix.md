# Bugfix Requirements Document

## Введение

При каждом перезапуске Telegram бота пользователи, которые ранее уже соглашались с политикой конфиденциальности, вынуждены соглашаться снова. Это происходит потому, что согласие пользователя не сохраняется в базу данных PostgreSQL.

Текст согласия: "Нажимая «Продолжить», вы соглашаетесь с политикой конфиденциальности (https://yandex.ru/legal/confidential/ru/) и правилами обработки персональных данных."

Данный баг негативно влияет на пользовательский опыт, заставляя пользователей повторно проходить процедуру согласия при каждом перезапуске бота.

## Анализ бага

### Текущее поведение (Дефект)

1.1 КОГДА пользователь дает согласие с политикой конфиденциальности, нажимая кнопку "✅ Согласен", ТО система НЕ сохраняет это согласие в базу данных PostgreSQL

1.2 КОГДА бот перезапускается после того, как пользователь уже дал согласие, ТО система снова запрашивает согласие у этого пользователя

1.3 КОГДА пользователь повторно заходит в бот после перезапуска, ТО система не находит записи о его предыдущем согласии и показывает запрос согласия заново

### Ожидаемое поведение (Корректное)

2.1 КОГДА пользователь дает согласие с политикой конфиденциальности, нажимая кнопку "✅ Согласен", ТО система ДОЛЖНА сохранить это согласие в отдельную таблицу PostgreSQL с полями: telegram_id, consent_date, created_at

2.2 КОГДА бот перезапускается после того, как пользователь уже дал согласие, ТО система ДОЛЖНА находить запись о согласии в базе данных и НЕ запрашивать согласие повторно

2.3 КОГДА пользователь повторно заходит в бот после перезапуска, ТО система ДОЛЖНА проверить наличие согласия в базе данных и пропустить этап запроса согласия, если оно уже было дано

### Неизменное поведение (Предотвращение регрессии)

3.1 КОГДА пользователь впервые заходит в бот и еще не давал согласие, ТО система ДОЛЖНА ПРОДОЛЖАТЬ запрашивать согласие с политикой конфиденциальности

3.2 КОГДА пользователь нажимает кнопку "🔙 Назад" на экране согласия, ТО система ДОЛЖНА ПРОДОЛЖАТЬ возвращать пользователя в главное меню без сохранения согласия

3.3 КОГДА пользователь дает согласие, ТО система ДОЛЖНА ПРОДОЛЖАТЬ запрашивать кодовое слово на следующем шаге

3.4 КОГДА пользователь с сохраненным согласием проверяет приз, ТО система ДОЛЖНА ПРОДОЛЖАТЬ корректно обрабатывать весь флоу проверки приза без повторного запроса согласия
