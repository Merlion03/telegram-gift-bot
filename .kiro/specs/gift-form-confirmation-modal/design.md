# Design Document: Gift Form Confirmation Modal

## Обзор

Модальное окно подтверждения данных формы физического подарка - это UI компонент, который предотвращает случайную отправку неверных данных доставки. Компонент перехватывает отправку формы, отображает все введённые данные для проверки пользователем и предоставляет возможность либо подтвердить отправку, либо вернуться к редактированию.

### Цели

- Повысить качество данных доставки за счёт дополнительной проверки перед отправкой
- Снизить количество ошибок при заполнении адресов доставки
- Предоставить пользователю удобный способ проверки всех введённых данных
- Обеспечить понятный UX с возможностью редактирования и повторной отправки

### Контекст интеграции

Модальное окно интегрируется с существующим компонентом `DeliveryForm` в Telegram WebApp. Форма использует:
- React Hook Form для управления состоянием формы
- Zod для валидации данных
- Telegram WebApp SDK для взаимодействия с ботом
- Tailwind CSS для стилизации с поддержкой Telegram темизации

## Архитектура

### Принципы проектирования

1. **Модульность**: Каждый логический блок в отдельном файле
2. **Единственная ответственность**: Разделение concerns между компонентами
3. **Масштабируемость**: Легкость добавления новых функций и изменения существующих
4. **Чистая архитектура**: Без костылей, только правильные решения

## Компоненты и интерфейсы

### 1. ConfirmationModal Component

**Ответственность**: Отображение модального окна с данными для подтверждения

**Props**:
```typescript
interface ConfirmationModalProps {
  isOpen: boolean;                    // Состояние открытия модального окна
  onClose: () => void;                // Callback для закрытия без подтверждения
  onConfirm: () => void;              // Callback для подтверждения отправки
  deliveryData: DeliveryData;         // Данные для отображения
  isSubmitting: boolean;              // Состояние процесса отправки
}
```

**Функциональность**:
- Отображение overlay с блокировкой прокрутки страницы
- Рендеринг данных доставки через `DeliveryDataDisplay`
- Кнопки "Отправить" и "Изменить"
- Кнопка закрытия (крестик) в правом верхнем углу
- Закрытие по клику вне модального окна
- Закрытие по нажатию Escape
- Управление фокусом (фокус на кнопку "Отправить" при открытии)
- Поддержка клавиатурной навигации (Tab, Enter, Escape)
- Адаптивный дизайн для мобильных устройств
- Использование Telegram темизации

### 2. DeliveryDataDisplay Component

**Ответственность**: Форматированное отображение данных доставки

**Props**:
```typescript
interface DeliveryDataDisplayProps {
  data: DeliveryData;                 // Данные для отображения
  className?: string;                 // Дополнительные CSS классы

```

**Функциональность**:
- Группировка данных по секциям (Получатель, Адрес, Контакты)

- Корректная обработка опциональных полей (patronymic, apartment, comment)
- Читаемое форматирование с подписями полей
- Использование Telegram цветовой схемы

### 3. useConfirmationModal Hook

**Ответственность**: Управление состоянием и логикой модального окна

**Interface**:
```typescript
interface UseConfirmationModalReturn {
```

**Функциональность**:
- Управление состоянием открытия/закрытия
- Сохранение данных для отображения
- Интеграция с процессом отправки формы
- Обработка успешной отправки и ошибок

## Поток данных

### 1. Открытие модального окна

```
User clicks "Отправить данные"
         ↓
DeliveryForm validates data
         ↓
DeliveryForm calls openModal(data)
         ↓
useConfirmationModal stores data and sets isOpen=true
         ↓
ConfirmationModal renders with data
         ↓
Focus moves to "Отправить" button
```

### 2. Подтверждение отправки

```
User clicks "Отправить" in modal
         ↓
ConfirmationModal calls onConfirm()
         ↓
useConfirmationModal calls confirmSubmit()
         ↓
DeliveryForm submits data to API
         ↓
On success: close modal, show success message, disable form
         ↓
On error: close modal, show error message, keep form editable
```

### 3. Возврат к редактированию

```
User clicks "Изменить" or close button or Escape or outside
         ↓
ConfirmationModal calls onClose()
         ↓
useConfirmationModal sets isOpen=false
         ↓
Modal closes, data remains in form fields
         ↓
User can edit and resubmit
```

## Correctness Properties

*Свойство (property) - это характеристика или поведение, которое должно выполняться для всех валидных входных данных системы. Свойства служат мостом между человекочитаемыми спецификациями и машинно-проверяемыми гарантиями корректности.*

### Property 1: Перехват отправки формы

*Для любой* валидной формы доставки, при нажатии кнопки "Отправить данные" форма должна предотвратить немедленную отправку HTTP запроса и вместо этого открыть модальное окно подтверждения.

**Validates: Requirements 1.1, 1.2**

### Property 2: Сохранение данных формы

*Для любых* введённых данных доставки, при любых операциях с модальным окном (открытие, закрытие через "Изменить", закрытие через Escape, закрытие кликом вне окна) данные должны сохраняться в полях формы до момента успешной отправки.

**Validates: Requirements 1.3, 4.3, 6.3**

### Property 3: Полнота отображения данных

*Для любых* данных доставки, модальное окно должно отображать все заполненные поля (обязательные: last_name, first_name, country, postal_code, city, street, house, phone; опциональные: patronymic, apartment, comment) с соответствующими подписями на русском языке.

**Validates: Requirements 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 2.10, 2.11**

### Property 4: Отправка данных при подтверждении

*Для любых* валидных данных доставки, при нажатии кнопки "Отправить" в модальном окне система должна отправить HTTP запрос с этими данными на API endpoint.

**Validates: Requirements 3.2**

### Property 5: Закрытие модального окна после успешной отправки

*Для любых* данных доставки, если отправка завершилась успешно (HTTP 200), модальное окно должно закрыться и отобразиться сообщение об успехе.

**Validates: Requirements 3.3**

### Property 6: Блокировка повторной отправки

*Для любых* данных доставки, после успешной отправки форма должна быть заблокирована для предотвращения повторной отправки тех же данных.

**Validates: Requirements 3.5**

### Property 7: Закрытие модального окна для редактирования

*Для любого* открытого модального окна, при нажатии кнопки "Изменить" модальное окно должно закрыться, а все поля формы должны остаться доступными для редактирования.

**Validates: Requirements 4.2, 4.4**

### Property 8: Round-trip редактирования данных

*Для любых* данных доставки, если пользователь открывает модальное окно, закрывает его для редактирования, изменяет данные и снова открывает модальное окно, то в модальном окне должны отображаться обновлённые данные.

**Validates: Requirements 4.5**

### Property 9: Обработка ошибок отправки

*Для любых* данных доставки, если отправка завершилась ошибкой (HTTP 4xx/5xx или network error), модальное окно должно закрыться, отобразиться сообщение об ошибке, данные должны сохраниться в форме, и форма должна оставаться доступной для повторной отправки.

**Validates: Requirements 5.1, 5.2, 5.3, 5.4**

### Property 10: Способы закрытия модального окна

*Для любого* открытого модального окна, пользователь должен иметь возможность закрыть его четырьмя способами: кнопка "Изменить", кнопка закрытия (крестик), клик вне модального окна, клавиша Escape - и во всех случаях данные должны сохраниться.

**Validates: Requirements 6.1, 6.2**

### Property 11: Валидация перед открытием модального окна

*Для любых* данных формы, модальное окно должно открываться только если все обязательные поля заполнены корректно; если есть ошибки валидации, должны отображаться сообщения об ошибках и модальное окно не должно открываться.

**Validates: Requirements 7.1, 7.2, 7.3**

### Property 12: Клавиатурная навигация

*Для любого* открытого модального окна, пользователь должен иметь возможность навигации с клавиатуры: Tab для перемещения между элементами, Enter для подтверждения, Escape для закрытия.

**Validates: Requirements 8.2**

### Property 13: Управление фокусом

*Для любого* открытия модального окна, фокус должен автоматически устанавливаться на кнопку "Отправить" для удобства клавиатурной навигации.

**Validates: Requirements 8.3**

### Property 14: Блокировка прокрутки

*Для любого* открытого модального окна, прокрутка основной страницы должна быть заблокирована (body должен иметь overflow: hidden).

**Validates: Requirements 8.4**

## Обработка ошибок

### Типы ошибок

1. **Ошибки валидации формы**
   - Обрабатываются на уровне `DeliveryForm` через react-hook-form
   - Предотвращают открытие модального окна
   - Отображаются под соответствующими полями формы

2. **Ошибки сети**
   - Перехватываются в `try-catch` блоке при отправке
   - Модальное окно закрывается
   - Отображается сообщение об ошибке через `ErrorMessage` компонент
   - Форма остаётся доступной для повторной попытки

3. **Ошибки API (4xx, 5xx)**
   - Обрабатываются проверкой `response.ok`
   - Парсится JSON ответ для получения детального сообщения
   - Модальное окно закрывается
   - Отображается сообщение об ошибке с деталями от API
   - Форма остаётся доступной для повторной попытки

4. **Ошибки Telegram WebApp SDK**
   - Проверка наличия `initData` перед отправкой
   - Отображение понятного сообщения пользователю
   - Предотвращение отправки без валидных Telegram данных

### Стратегия обработки

```typescript
try {
  // Попытка отправки данных
  const response = await fetch('/api/delivery', { ... });
  
  if (!response.ok) {
    // Обработка HTTP ошибок
    const errorData = await response.json();
    throw new Error(errorData.error || errorData.message);
  }
  
  // Успех: закрыть модальное окно, показать сообщение
  closeModal();
  showSuccessMessage();
  disableForm();
  
} catch (error) {
  // Обработка любых ошибок
  closeModal();
  setError(getReadableErrorMessage(error));
  // Форма остаётся активной для повторной попытки
}
```

### Пользовательские сообщения

- **Сеть недоступна**: "Не удалось подключиться к серверу. Проверьте интернет-соединение."
- **Ошибка сервера**: "Произошла ошибка на сервере. Попробуйте позже."
- **Невалидные данные**: Конкретное сообщение от API о проблеме
- **Отсутствие Telegram данных**: "InitData недоступны. Откройте форму через Telegram."

## Стратегия тестирования

- **Unit-тесты**: Проверяют конкретные примеры, edge cases и интеграционные точки
- **Property-тесты**: Проверяют универсальные свойства на большом количестве сгенерированных входных данных

### Edge Cases

1. **Пустые опциональные поля**: patronymic, apartment, comment не заполнены
2. **Максимальная длина полей**: Все поля заполнены максимально допустимым количеством символов
3. **Минимальная длина полей**: Все поля заполнены минимально допустимым количеством символов
4. **Специальные символы**: Адреса с дефисами, слешами, номерами домов типа "10А"
5. **Международные номера**: Телефоны с различными кодами стран
6. **Быстрое открытие/закрытие**: Множественные быстрые клики на кнопки
7. **Отправка во время загрузки**: Попытка повторной отправки пока идёт первая

### Integration Testing

1. **Полный flow успешной отправки**:
   - Заполнение формы → Открытие модального окна → Подтверждение → Успешная отправка → Блокировка формы

2. **Flow с редактированием**:
   - Заполнение формы → Открытие модального окна → Закрытие для редактирования → Изменение данных → Повторное открытие → Подтверждение

3. **Flow с ошибкой**:
   - Заполнение формы → Открытие модального окна → Подтверждение → Ошибка отправки → Отображение ошибки → Повторная попытка

4. **Клавиатурная навигация**:
   - Навигация Tab между элементами → Enter для подтверждения → Escape для закрытия
