# Документ требований: Telegram Bot WebApp System

## Введение

Система представляет собой комплексное решение для проведения розыгрышей через Telegram-бота с интеграцией Google Sheets для хранения данных участников и Next.js приложением для сбора данных доставки и администрирования службы поддержки. Система обеспечивает автоматическую проверку победителей, выдачу призов и real-time коммуникацию между пользователями и службой поддержки.

## Глоссарий

- **Bot**: Telegram-бот, реализованный на Python с использованием aiogram 3.x
- **WebApp**: Next.js приложение, открываемое внутри Telegram через Telegram WebApp SDK
- **Admin_Panel**: Административная панель для службы поддержки, реализованная в Next.js
- **Google_Sheets_API**: API для работы с Google Таблицами через библиотеки gspread и google-auth
- **Prize_Database**: Google Таблица, содержащая данные о победителях и призах
- **Support_Database**: PostgreSQL база данных для хранения сообщений службы поддержки
- **FSM_State**: Состояние конечного автомата (Finite State Machine) для управления диалогами
- **Telegram_ID**: Уникальный идентификатор пользователя в Telegram
- **Promo_Code**: Промокод для получения цифрового приза
- **Physical_Prize**: Физический приз, требующий данных доставки
- **Digital_Prize**: Цифровой приз (промокод)
- **InitData**: Криптографически подписанные данные от Telegram WebApp
- **Support_Session**: Сессия общения пользователя со службой поддержки

## Требования

### Требование 1: Проверка участия в розыгрыше

**User Story:** Как пользователь, я хочу проверить, выиграл ли я приз, отправив кодовое слово боту, чтобы узнать результат розыгрыша.

#### Критерии приёмки

1. WHEN пользователь отправляет кодовое слово боту, THE Bot SHALL запросить Telegram_ID пользователя
2. WHEN Bot получает Telegram_ID, THE Bot SHALL выполнить поиск этого ID в указанном столбце Prize_Database через Google_Sheets_API
3. IF Telegram_ID не найден в Prize_Database, THEN THE Bot SHALL отправить пользователю сообщение «Вы ещё не победили в конкурсе»
4. WHEN поиск в Prize_Database выполняется, THE Bot SHALL обработать запрос в течение 3 секунд
5. IF Google_Sheets_API недоступен, THEN THE Bot SHALL отправить пользователю сообщение об ошибке и повторить попытку

### Требование 2: Выдача цифрового приза

**User Story:** Как победитель с цифровым призом, я хочу получить промокод и инструкцию, чтобы воспользоваться своим выигрышем.

#### Критерии приёмки

1. WHEN Telegram_ID найден в Prize_Database И тип приза указан как Digital_Prize, THE Bot SHALL извлечь Promo_Code из соответствующей ячейки таблицы
2. WHEN Promo_Code извлечён, THE Bot SHALL отправить пользователю сообщение с промокодом
3. WHEN Bot отправляет Promo_Code, THE Bot SHALL включить инструкцию по использованию промокода
4. WHEN цифровой приз выдан, THE Bot SHALL отметить в Prize_Database, что приз был получен пользователем
5. IF Promo_Code отсутствует в таблице, THEN THE Bot SHALL уведомить администратора и сообщить пользователю о необходимости обратиться в поддержку

### Требование 3: Выдача физического приза

**User Story:** Как победитель с физическим призом, я хочу указать данные для доставки, чтобы получить свой выигрыш.

#### Критерии приёмки

1. WHEN Telegram_ID найден в Prize_Database И тип приза указан как Physical_Prize, THE Bot SHALL отправить пользователю Inline-кнопку с параметром web_app
2. WHEN пользователь нажимает на Inline-кнопку, THE Bot SHALL открыть WebApp внутри Telegram
3. WHEN WebApp открывается, THE WebApp SHALL отобразить форму для ввода данных доставки
4. WHEN WebApp открывается, THE WebApp SHALL передать InitData для криптографической валидации
5. THE WebApp SHALL запрашивать следующие поля: ФИО, адрес доставки, номер телефона, комментарий (опционально)

### Требование 4: Валидация и сохранение данных доставки

**User Story:** Как система, я должна безопасно валидировать и сохранять данные доставки, чтобы обеспечить защиту пользовательских данных.

#### Критерии приёмки

1. WHEN пользователь заполняет форму в WebApp, THE WebApp SHALL валидировать все обязательные поля на стороне клиента
2. WHEN пользователь отправляет форму, THE WebApp SHALL отправить данные на Next.js API endpoint с InitData
3. WHEN Next.js API получает данные, THE Next.js API SHALL выполнить криптографическую проверку InitData с использованием токена бота
4. IF InitData невалидны, THEN THE Next.js API SHALL отклонить запрос с HTTP статусом 403
5. WHEN InitData валидны, THE Next.js API SHALL записать данные доставки в соответствующую строку Prize_Database через Google_Sheets_API
6. WHEN данные успешно сохранены, THE WebApp SHALL отобразить сообщение об успехе и закрыться
7. IF запись в Prize_Database не удалась, THEN THE WebApp SHALL отобразить сообщение об ошибке и предложить повторить попытку

### Требование 5: Инициация сессии поддержки

**User Story:** Как пользователь, я хочу связаться со службой поддержки, чтобы получить помощь по моему вопросу.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку «Позвать человека», THE Bot SHALL создать новую Support_Session в Support_Database
2. WHEN Support_Session создана, THE Bot SHALL перевести пользователя в FSM_State поддержки
3. WHEN пользователь находится в FSM_State поддержки, THE Bot SHALL отобразить кнопку «Завершить диалог»
4. WHEN пользователь переведён в FSM_State поддержки, THE Bot SHALL отправить подтверждающее сообщение «Вы соединены с поддержкой. Опишите ваш вопрос»
5. WHEN Support_Session создаётся, THE Bot SHALL записать Telegram_ID пользователя, timestamp начала сессии и статус «активна»

### Требование 6: Обработка сообщений в режиме поддержки

**User Story:** Как пользователь в режиме поддержки, я хочу отправлять сообщения службе поддержки, чтобы получить помощь.

#### Критерии приёмки

1. WHILE пользователь находится в FSM_State поддержки, THE Bot SHALL перехватывать все входящие сообщения от пользователя
2. WHEN Bot перехватывает сообщение в FSM_State поддержки, THE Bot SHALL сохранить сообщение в Support_Database с привязкой к Support_Session
3. WHEN сообщение сохранено в Support_Database, THE Bot SHALL записать Telegram_ID отправителя, текст сообщения, timestamp и тип «от пользователя»
4. WHEN сообщение сохранено, THE Bot SHALL НЕ выполнять стандартную обработку команд (кроме команды завершения диалога)
5. WHEN пользователь отправляет медиа-контент (фото, документы), THE Bot SHALL сохранить file_id в Support_Database

### Требование 7: Real-time отображение сообщений в админке

**User Story:** Как сотрудник поддержки, я хочу видеть новые сообщения от пользователей в реальном времени, чтобы оперативно реагировать на запросы.

#### Критерии приёмки

1. WHEN новое сообщение записывается в Support_Database, THE Support_Database SHALL отправить уведомление через WebSocket или Supabase Realtime
2. WHEN Admin_Panel получает уведомление о новом сообщении, THE Admin_Panel SHALL отобразить сообщение в интерфейсе без перезагрузки страницы
3. WHEN Admin_Panel отображает сообщение, THE Admin_Panel SHALL показать Telegram_ID отправителя, текст сообщения и timestamp
4. WHEN Admin_Panel загружается, THE Admin_Panel SHALL отобразить все активные Support_Session
5. WHEN сотрудник поддержки выбирает Support_Session, THE Admin_Panel SHALL отобразить полную историю переписки

### Требование 8: Отправка ответов из админки

**User Story:** Как сотрудник поддержки, я хочу отвечать пользователям из админки, чтобы решать их вопросы.

#### Критерии приёмки

1. WHEN сотрудник поддержки вводит ответ в Admin_Panel, THE Admin_Panel SHALL отправить сообщение на Next.js API endpoint
2. WHEN Next.js API получает сообщение от Admin_Panel, THE Next.js API SHALL сохранить сообщение в Support_Database с типом «от поддержки»
3. WHEN сообщение сохранено в Support_Database, THE Next.js API SHALL вызвать метод sendMessage Telegram Bot API
4. WHEN Telegram Bot API вызван, THE Next.js API SHALL отправить сообщение пользователю с указанным Telegram_ID
5. WHEN сообщение отправлено пользователю, THE Admin_Panel SHALL отобразить сообщение в истории переписки с отметкой «доставлено»
6. IF отправка сообщения не удалась, THEN THE Admin_Panel SHALL отобразить ошибку и предложить повторить попытку

### Требование 9: Завершение сессии поддержки

**User Story:** Как пользователь, я хочу завершить диалог с поддержкой, чтобы вернуться к обычному режиму работы с ботом.

#### Критерии приёмки

1. WHEN пользователь нажимает кнопку «Завершить диалог», THE Bot SHALL изменить статус Support_Session на «завершена» в Support_Database
2. WHEN Support_Session завершена, THE Bot SHALL вывести пользователя из FSM_State поддержки
3. WHEN пользователь выведен из FSM_State поддержки, THE Bot SHALL отправить сообщение «Диалог завершён. Спасибо за обращение!»
4. WHEN пользователь выведен из FSM_State поддержки, THE Bot SHALL восстановить стандартную обработку команд
5. WHEN Support_Session завершена, THE Admin_Panel SHALL обновить статус сессии в интерфейсе

### Требование 10: Безопасность WebApp

**User Story:** Как система, я должна обеспечить криптографическую защиту WebApp, чтобы предотвратить несанкционированный доступ.

#### Критерии приёмки

1. WHEN WebApp отправляет данные на Next.js API, THE WebApp SHALL включить InitData в запрос
2. WHEN Next.js API получает запрос с InitData, THE Next.js API SHALL извлечь hash из InitData
3. WHEN hash извлечён, THE Next.js API SHALL вычислить ожидаемый hash используя секретный ключ бота и данные из InitData
4. WHEN ожидаемый hash вычислен, THE Next.js API SHALL сравнить его с полученным hash
5. IF hash не совпадают, THEN THE Next.js API SHALL отклонить запрос с HTTP статусом 403 и сообщением «Invalid signature»
6. THE Next.js API SHALL проверять timestamp в InitData и отклонять запросы старше 24 часов

### Требование 11: Безопасность админки

**User Story:** Как система, я должна защитить админку от несанкционированного доступа, чтобы только авторизованные сотрудники могли работать с поддержкой.

#### Критерии приёмки

1. WHEN пользователь пытается открыть Admin_Panel, THE Admin_Panel SHALL проверить наличие активной сессии авторизации
2. IF активная сессия отсутствует, THEN THE Admin_Panel SHALL перенаправить пользователя на страницу входа
3. WHEN пользователь вводит учётные данные, THE Admin_Panel SHALL использовать NextAuth.js для аутентификации
4. WHEN аутентификация успешна, THE Admin_Panel SHALL создать защищённую сессию с токеном
5. WHEN пользователь авторизован, THE Admin_Panel SHALL предоставить доступ к функциям поддержки
6. THE Admin_Panel SHALL автоматически завершать сессию после 8 часов неактивности

### Требование 12: Защита от XSS

**User Story:** Как система, я должна защищать от XSS-атак, чтобы предотвратить выполнение вредоносного кода.

#### Критерии приёмки

1. WHEN WebApp или Admin_Panel отображают пользовательский контент, THE приложение SHALL экранировать все HTML-теги
2. THE WebApp и Admin_Panel SHALL НЕ использовать dangerouslySetInnerHTML для отображения пользовательского контента
3. WHEN приложение обрабатывает пользовательский ввод, THE приложение SHALL валидировать и санитизировать данные на стороне сервера
4. THE Next.js API SHALL использовать Content Security Policy (CSP) заголовки для предотвращения загрузки внешних скриптов
5. WHEN приложение отображает URL из пользовательского ввода, THE приложение SHALL валидировать протокол (разрешены только http/https)

### Требование 13: Управление секретами

**User Story:** Как система, я должна безопасно хранить и использовать секретные данные, чтобы предотвратить их утечку.

#### Критерии приёмки

1. THE Bot, WebApp и Admin_Panel SHALL читать все токены и ключи доступа исключительно из переменных окружения
2. THE система SHALL НЕ хранить секретные данные в исходном коде
3. THE система SHALL использовать файл .env для локальной разработки
4. THE .env файл SHALL быть добавлен в .gitignore
5. WHEN приложение логирует ошибки, THE приложение SHALL НЕ включать секретные данные в логи
6. THE система SHALL использовать отдельные наборы секретов для разработки и продакшена

### Требование 14: Модульная архитектура бота

**User Story:** Как разработчик, я хочу иметь модульную архитектуру бота, чтобы легко добавлять новые функции и поддерживать код.

#### Критерии приёмки

1. THE Bot SHALL разделять функциональность на независимые модули (handlers, services, database, api_clients)
2. WHEN создаётся новый логический блок, THE Bot SHALL размещать его в отдельном файле
3. THE Bot SHALL использовать dependency injection для передачи зависимостей между модулями
4. THE Bot SHALL иметь отдельные модули для: обработки команд, работы с Google Sheets, работы с БД, FSM-логики
5. WHEN модуль изменяется, THE изменение SHALL НЕ требовать модификации других модулей (принцип единственной ответственности)

### Требование 15: Модульная архитектура Next.js приложения

**User Story:** Как разработчик, я хочу иметь модульную архитектуру Next.js приложения, чтобы легко масштабировать и поддерживать систему.

#### Критерии приёмки

1. THE Next.js приложение SHALL разделять функциональность на: API routes, компоненты, сервисы, утилиты
2. WHEN создаётся новый API endpoint, THE endpoint SHALL быть в отдельном файле
3. THE Next.js приложение SHALL использовать отдельные модули для: валидации InitData, работы с Google Sheets API, работы с Telegram Bot API, работы с БД
4. THE компоненты WebApp и Admin_Panel SHALL быть разделены на независимые переиспользуемые части
5. THE Next.js приложение SHALL использовать TypeScript для типобезопасности

### Требование 16: Обработка ошибок

**User Story:** Как система, я должна корректно обрабатывать ошибки, чтобы обеспечить стабильную работу и информировать пользователей о проблемах.

#### Критерии приёмки

1. WHEN возникает ошибка при работе с Google_Sheets_API, THE система SHALL логировать ошибку и повторить попытку до 3 раз
2. IF все попытки исчерпаны, THEN THE система SHALL уведомить пользователя о временной недоступности сервиса
3. WHEN возникает ошибка при работе с Support_Database, THE Bot SHALL логировать ошибку и уведомить администратора
4. WHEN возникает ошибка в WebApp, THE WebApp SHALL отобразить понятное сообщение об ошибке пользователю
5. THE система SHALL логировать все критические ошибки с полным stack trace для отладки
6. THE система SHALL использовать структурированное логирование (JSON format) для упрощения анализа

### Требование 17: Производительность и масштабируемость

**User Story:** Как система, я должна обеспечивать высокую производительность и масштабируемость, чтобы обслуживать большое количество пользователей.

#### Критерии приёмки

1. THE Bot SHALL использовать асинхронную обработку запросов через aiogram 3.x
2. WHEN Bot обрабатывает запросы к Google_Sheets_API, THE Bot SHALL использовать connection pooling
3. THE Support_Database SHALL использовать индексы на полях Telegram_ID и timestamp для быстрого поиска
4. THE Admin_Panel SHALL использовать пагинацию при отображении списка Support_Session (максимум 50 сессий на страницу)
5. THE система SHALL поддерживать горизонтальное масштабирование Bot через использование webhook вместо polling (опционально)
