## Первопричина

Метод `_sync_sheet_delivery_data` в файле `telegram-bot/services/sync_service.py` (строка 1059) использует неправильный диапазон обновления:

```python
# ТЕКУЩИЙ КОД (НЕПРАВИЛЬНО):
cell_range = f'E{prize.row_id}:P{prize.row_id}'
```

Этот диапазон включает 12 столбцов: E, F, G, H, I, J, K, L, M, N, O, P

**Проблема:** Столбцы E и F уже заняты данными цифрового приза:
- Столбец E: promo_code (промокод)
- Столбец F: instructions (инструкция)

При записи данных доставки в диапазон E:P, первые два элемента массива `row_data` (last_name и first_name) перезаписывают столбцы E и F, уничтожая промокод и инструкцию.

## Структура данных

### Текущая структура (НЕПРАВИЛЬНАЯ):

Диапазон E:P (12 столбцов):
- E (5): last_name → **ПЕРЕЗАПИСЫВАЕТ promo_code**
- F (6): first_name → **ПЕРЕЗАПИСЫВАЕТ instructions**
- G (7): patronymic
- H (8): city
- I (9): street
- J (10): house
- K (11): apartment
- L (12): phone
- M (13): comment
- N (14): country
- O (15): postal_code
- P (16): claimed_at

### Правильная структура (ОЖИДАЕМАЯ):

Столбцы A-F: Неизменяемые данные
- A: telegram_id
- B: username
- C: code_word
- D: prize_type
- E: promo_code (НЕ ТРОГАТЬ)
- F: instructions (НЕ ТРОГАТЬ)

Диапазон G:R (12 столбцов) - данные доставки:
- G (7): last_name
- H (8): first_name
- I (9): patronymic
- J (10): city
- K (11): street
- L (12): house
- M (13): apartment
- N (14): phone
- O (15): comment
- P (16): country
- Q (17): postal_code
- R (18): claimed_at

## Решение

Изменить строку 1059 в `telegram-bot/services/sync_service.py`:

```python
# ИСПРАВЛЕННЫЙ КОД:
cell_range = f'G{prize.row_id}:R{prize.row_id}'
```

Это изменение:
1. Сохранит столбцы E (promo_code) и F (instructions) нетронутыми
2. Запишет данные доставки в правильные столбцы G-R
3. Не повлияет на forward sync (чтение данных)
4. Не повлияет на backward sync для физических призов
