## Анализ Корневой Причины

### Подтверждённые Проблемы

1. **Отсутствие обработки канала `new_message`**
   - Метод `createMessageFromPayload()` не содержит case для канала `new_message`
   - Канал не документирован в константах и не обрабатывается в коде
   - Результат: возврат `null` и логирование предупреждения

2. **Отсутствие маршрутизации к подписчикам**
   - Даже если бы канал обрабатывался, нет логики для определения целевых подписчиков
   - Уведомление содержит `session_id` в payload, который нужно использовать для маршрутизации
   - Необходима маршрутизация к двум типам подписчиков: `session_*` и `all_messages`

3. **Несоответствие структуры payload**
   - Триггер отправляет payload с вложенной структурой `data`
   - Текущие методы ожидают плоскую структуру `PostgresNewMessagePayload`
   - Необходим специальный метод для парсинга payload от триггера

### Необходимые Исправления

1. Добавить обработку канала `new_message` в метод `createMessageFromPayload()`
2. Создать метод `createNewMessageFromTrigger()` для парсинга вложенной структуры payload
3. Создать метод `determineSenderType()` для определения типа отправителя
4. Создать метод `getTargetChannels()` для определения списка целевых каналов
5. Модифицировать метод `handleNotification()` для поддержки маршрутизации к нескольким каналам
